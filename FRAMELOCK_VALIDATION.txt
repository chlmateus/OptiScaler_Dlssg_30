OptiScaler + FrameLock integration validation
============================================

Source basis
------------
User-uploaded OptiScaler-master.zip was used directly as the baseline.

Architecture
------------
PASS - FrameLock is integrated behind existing FrameLimit::sleep() calls.
PASS - No standalone FrameLock DXGI factory hook added.
PASS - No standalone FrameLock Present/Present1 hook added.
PASS - No standalone FrameLock ASI/control-panel path added.
PASS - Existing DXGI, FG and Vulkan paths route to the internal limiter when FrameLock is selected.
PASS - Reflex/Anti-Lag low-latency behavior is retained while its FPS interval is cleared for forced internal limiting.
PASS - XeLL low-latency behavior is retained while its FPS interval is cleared for forced internal limiting.

Timing implementation
---------------------
PASS - QPC is the FrameLock scheduler clock.
PASS - Persistent fractional deadline accumulator is used.
PASS - High-resolution waitable timer with normal-timer fallback is used.
PASS - Final precision spin is hard bounded by MaxSpinThresholdUs.
PASS - Excess adaptive wake margin uses cooperative yielding rather than extending busy spin.
PASS - Large deadline misses resynchronize instead of burst catch-up.
PASS - Overshoot calibration rejects samples beyond the configured ceiling.
PASS - Rolling statistics use fixed-size storage and atomically published telemetry.
PASS - No disk writes are performed by the FrameLock wait path.

Portable compiler check
-----------------------
PASS - FrameLockLimiter.cpp passes clang++ C++20 -Wall -Wextra -Wpedantic syntax checking with Win32 timing calls stubbed.
This validates C++ syntax/template usage but is not a substitute for MSVC + Windows SDK compilation.

Fractional deadline test
------------------------
PASS - 100,000-deadline phase-distribution test at a simulated 10 MHz QPC for:
30, 36, 48, 59.94, 71.9995, 72, 90, 119.88, 120, 138, 141, 143.999, 144 FPS.
All average interval errors were below 0.0001 QPC tick.
